## 0. 무엇이 문제인가

UI가 전부 코드로 지어지고(`UiKit`), 창마다 **자기 색 · 자기 글자 크기를 파일 맨 위에 따로 적는다.** 그래서 각 창은 멀쩡한데 나란히 놓으면 다른 게임이다.

| 항목 | 지금 | 증상 |
| --- | --- | --- |
| 색 | UI · 흐름 스크립트에 `new Color(...)` **110개 이상**. `RunMapScreen` 혼자 22개 | 같은 뜻의 색이 파일마다 미세하게 다르다 |
| 금색 | `(1, .86, .45)` · `(1, .82, .40)` · `(1, .878, .40)` 세 벌 | 눈으로는 같고 값은 다르다 — 하나 고치면 나머지가 남는다 |
| 판(패널) 색 | `HudLayout.PlateColor (.06,.07,.09,.82)` · `(.08,.09,.11)` · `(.10,.10,.12,.97)` · `(.11,.12,.15,.98)` | 창이 겹치면 판의 검정이 서로 다르게 보인다 |
| 금색의 역할 | 제목(`TitleColor`) **이자** 포커스(`FocusColor`) — `CardRewardSession` · `RunMapScreen` | "지금 고른 것"과 "그냥 제목"이 같은 색이라 포커스가 묻힌다 |
| 글자 크기 | 13 · 14 · 15 · 16 · 17 · 18 · 20 · 22 · 24 · 26 · 28 · 30 · 34 · 38 · 40 · 48 · 56 — **17단계** | 위계가 없다. 15와 16, 17과 18이 서로 다른 뜻인지 아무도 모른다 |
| 글꼴 | `LegacyRuntime.ttf`(내장) — 한글 글리프가 없어 OS 대체 글꼴로 그려진다 | 기기마다 모양이 다르고, 두께 · 자간을 정할 수 없다 |
| 글자 외곽선 | 없음 | 배경 일러스트(이벤트 배경 · 전투) 위에서 글자가 묻힌다 |
| 창의 골격 | `NodeWindows.Panel` · `PauseMenu` · `StageResultUI` · `CardRewardSession` · `PartySelectUI`가 바탕막 · 판 · 제목 · 버튼 줄을 각자 짓는다 | 제목 위치, 버튼 크기, 여백이 창마다 다르다 |
| 화면 귀퉁이 | 좌상단 덱 상황판, 우상단 [처음부터] · [ESC 일시정지], 우측 콤보 — 각자 자리를 잡았다 | "런 정보는 어디 보면 되나"가 씬마다 다르다 |

한 줄로: **부품은 있는데 규격이 없다.** 이 기획은 규격(토큰)과 규격 부품(컴포넌트)을 먼저 정하고, 화면을 그 위로 옮긴다.

## 1. 레퍼런스에서 뽑은 원리 — 왜 한 게임처럼 읽히나

두 장면은 전혀 다른 화면(이벤트 / 전투)인데 같은 게임으로 읽힌다. 이유를 일곱 개로 나눈다.

| # | 원리 | 레퍼런스에서 보이는 것 | 우리 쪽 대응 |
| --- | --- | --- | --- |
| R1 | **상단 바는 모든 런 화면에 똑같이 있다** | 이벤트 · 전투 둘 다 같은 바: 초상 · 체력 · 골드 · 포션 칸 · 층 · 보스 / 우측 지도 · 덱 · 설정 | 런 동안의 모든 씬(지도 · 전투 · 칸)에 같은 **런 바**를 띄운다(5.1) |
| R2 | **판은 한 종류다** — 어두운 반투명 판 + 얇은 밝은 테두리 + 둥근 모서리 | 대사 줄, 선택지, 툴팁, 턴 종료 버튼이 전부 같은 재질 | 판을 3종(바탕판 · 테두리판 · 오목판)으로 고정한다(3.4) |
| R3 | **색이 뜻을 가진다** — 빨강=체력, 금=재화 · 제목 · 키워드, 청록=지금 고른 것, 파랑=방어, 초록=강화된 수치 | 선택지 제목 금색, 본문 흰색, 키워드만 금색, 고른 선택지만 청록 테두리 | 의미 색 표를 만들고 그 밖의 색은 UI에 못 쓰게 한다(3.1) |
| R4 | **숫자는 크고 굵고 외곽선이 있다** | 80/80, 288, 18, 1/3 — 어떤 배경 위에서도 읽힌다 | 모든 글자에 외곽선/그림자, 숫자는 한 단계 큰 굵은체(3.2) |
| R5 | **아이콘 + 숫자가 한 묶음** | 하트+80/80, 동전+288, 계단+18. 개수는 아이콘 귀퉁이의 동그란 배지(덱 20, 뽑을 더미 2, 버린 더미 18) | `IconStat` · `Badge` 부품(4항) |
| R6 | **선택지는 같은 줄 모양이다** — 왼쪽 아이콘, 금색 제목, 흰 설명. 마우스를 올리면 툴팁이 옆에, 관련 카드가 반대편에 | 이벤트 선택지 3줄 + 왼쪽 "사용불가" 툴팁 + 오른쪽 카드 | `OptionRow` + `Tooltip` + `CardView` 조합(4항). 칸 화면 레이아웃 개편은 하지 않는다(9항) |
| R7 | **화면 가장자리가 영역별로 고정** — 위: 런 정보, 왼아래: 자원(에너지 · 뽑을 더미), 오른아래: 행동(턴 종료 · 버린 더미), 유닛 밑: 그 유닛의 상태 | 전투 화면 전체 | 1920×1080 영역 지도를 정해 HUD를 배치한다(5.2) |

## 2. 우리 원칙 다섯

1. **토큰 밖의 값은 없다.** 색 · 글자 크기 · 여백 · 판은 `UiTheme`에서만 꺼낸다. 파일 맨 위의 `private static readonly Color ...`는 사라진다.
2. **금은 "이름", 청록은 "지금".** 금색은 제목 · 재화 · 키워드. 포커스 · 호버 · 선택은 청록 하나뿐이다.
3. **모든 글자는 어떤 배경 위에서도 읽힌다.** 외곽선 또는 그림자 없는 `Text`를 만들 수 없게 `UiKit.NewText`가 기본으로 붙인다.
4. **창은 골격이 하나다.** 바탕막 → 판 → 제목 띠 → 본문 → 버튼 줄. 창이 다른 것은 본문뿐이다(`UiKit.Modal`).
5. **자리는 씬이 아니라 영역이 정한다.** "런 정보는 위, 내 상태는 왼아래, 행동은 오른아래, 적 정보는 적 밑" — 지도 · 전투 · 칸이 같은 규칙을 쓴다.

| 토큰 | 크기 | 굵기 | 쓰는 곳 | 흡수 |

- **글꼴**: 한글 지원 OFL 글꼴 1종(굵기 2개)을 `Resources/Fonts/`에 넣고 `UiKit.Font`가 그것을 쓴다 — **결정 필요 D1**. TMP 전환은 이 기획 범위 밖(`UiKit`의 "Essential Resources 없음" 사유가 그대로 유효).

### 3.3 키워드 강조 — 리치 텍스트

레퍼런스는 설명문 속 핵심어만 금색이다("덱에서 카드를 **4장 제거**합니다. **뽑을 카드 더미**…"). 레거시 `Text`도 `<color>`를 지원하므로:

```
UiText.Kw("뽑을 카드 더미")      → <color=#FFDB73>뽑을 카드 더미</color>
UiText.Num(9, baseValue: 5)      → <color=#7BE07B>9</color>   (기본보다 크면 Buff, 작으면 Hp, 같으면 TextMain)
```

카드 · 스킬 설명 데이터에는 `{kw:…}` · `{n:…}` 표식만 적고, 그리는 쪽이 `UiText.Format`으로 바꾼다. 데이터에 색 코드를 직접 적지 않는다.

### 3.4 판 · 테두리 · 모서리

| 판 | 모양 | 쓰는 곳 |
| --- | --- | --- |
| `Plate` | `Ink` 바탕, 모서리 반경 10, 테두리 없음 | HUD 판(초상 묶음), 대사 줄 |
| `FramedPlate` | `Plate` + `Rim` 1.5px 테두리 | 창(모달), 선택지 줄, 툴팁, 버튼 |
| `Well` | `InkDeep`, 안쪽 그림자, 모서리 반경 6 | 빈 슬롯, 게이지 홈, 포션 · 총공격 슬롯 |

세 판 모두 **9-slice 스프라이트 한 장씩**으로 만든다(`Assets/Art/Ui/Plate_*.png`). 단색 `Image`로 버티는 지금 방식은 1단계까지만 허용한다.

### 3.5 간격 · 크기

- 간격은 **4의 배수**: `S4 · S8 · S12 · S16 · S24 · S32 · S48`. 화면 가장자리 여백 = `S32`(현재 `HudLayout.MarginX 36` · `MarginBottom 32` → 32로 맞춘다).
- 버튼 높이 3종: `Small 40` · `Medium 56` · `Large 72`. 버튼 폭은 라벨에 맞추되 최소 160.
- 아이콘 3종: `16`(인라인) · `32`(스탯) · `48`(선택지 · 상단 바).

### 3.6 움직임

| 토큰 | 길이 | 곡선 | 쓰는 곳 |
| --- | --- | --- | --- |
| `Quick` | 0.08s | ease-out | 호버 테두리 켜짐, 버튼 눌림 |
| `Normal` | 0.18s | ease-out | 창 열림(아래 16px에서 올라오며 페이드), 툴팁 |
| `Slow` | 0.35s | ease-in-out | 화면 전환 안의 패널 이동, 체력 잔상 |

모든 UI 애니메이션은 **unscaled time**으로 돈다 — 일시정지(`timeScale 0`)와 불릿타임(`TimeControl`) 중에도 UI는 살아 있어야 한다.

### 4.1 상호작용 상태 — 전 화면 공통

| 상태 | 표현 |
| --- | --- |
| 기본 | `FramedPlate`, 테두리 `Rim` |
| 호버 / 키보드 포커스 | 테두리 `Focus` 2px + 바깥 발광(`Focus` α .35, 8px) + 0.08s에 1.02배 |
| 누름 | 0.98배, 바탕 10% 밝게 |
| 선택됨(토글 · 고른 슬롯) | 테두리 `Focus` 유지 + 좌측 4px `Focus` 막대 |

## 8. 씬 재생 확인 목록 (테스트로 못 잡는 것)

단계마다 해당 줄만 본다.

- [ ] 마우스 호버와 방향키 포커스가 **같은 청록 테두리**로 보이고, 둘이 동시에 두 곳을 가리키지 않는다.
- [ ] 금색은 제목 · 재화 · 키워드에만, 청록은 고른 것에만 보인다 — 화면을 흑백 캡처했을 때도 포커스가 구분된다(발광 덕분).
- [ ] 일시정지 중(`timeScale 0`)과 불릿타임 중에 창 열림 · 호버 애니메이션이 정상 속도로 돈다.
- [ ] 지도 → 전투 → 칸 → 지도로 오가는 동안 런 바가 같은 자리 · 같은 모양이다.
- [ ] 21:9 · 16:10 해상도에서 런 바가 양 끝까지 늘어나고, 좌하단 묶음 · 콤보가 가장자리에서 `S32` 떨어져 있다.
- [ ] 적 여럿을 광역기로 맞혔을 때 적 막대 숫자들이 서로 겹쳐 읽기 어렵지 않다.
- [ ] 창이 겹치는 순간(일시정지 → 조작키) 판의 검정이 같은 색이다.

## 9. 범위 밖

- **칸 화면(휴식 · 상점 · 이벤트) 레이아웃 개편** — 제외로 결정. 배경 일러스트 + 대사 줄 + 선택지 줄 구성은 하지 않는다. 칸 창은 0 · 1단계의 색 · 글꼴 · 외곽선만 받은 지금 모양을 유지한다.

- TMP 전환 — 글꼴 하나로 얻을 이득을 이 기획이 먼저 얻는다. 전환은 asmdef 분리와 함께 따로.
- 스킬 VFX 색 정리 — 월드 연출은 아트 결정.
- 현지화 — 다만 3.3의 `{kw:…}` 표식은 번역 시 키워드 위치가 바뀌어도 그대로 동작하도록 정한 것이다.
