## 1. 무엇을 넣었나

이 게임에는 **런 도중에 강해지는 축이 없었다.** 덱 16장은 `Ally.Equipped`(동료 4명 × 4장)로
씬이 뜰 때마다 똑같이 짜였고 스테이지를 넘어가도 그대로였다. `EnemyData.exp`와
`GameManager.TotalExp`는 필드만 있고 **아무도 읽지 않았다.**

여기에 로그라이크식 성장 루프를 넣었다.

```text
적 처치 → 경험치 적립 → [라운드 클리어] → 레벨업 단계 선택 → 카드 3장 중 1장 선택 → 즉시 손패
                                              ↑                                        │
                                              └──────── 남은 경험치로 반복 ─────────────┘
```

| 축 | 내용 |
| :--- | :--- |
| **경험치** | 적을 죽이면 `EnemyData.exp`(기본 10)만큼 적립 |
| **사용 시점** | 아레나 클리어 / 웨이브 클리어 직후 — **다음 구간으로 넘어가기 전** |
| **3단계** | 비쌀수록 황금 카드 확률이 오른다. 레벨 상승폭은 단계와 무관하게 항상 +1 |
| **황금 카드** | 데미지 ×1.5, 테두리가 금색 |
| **합성** | 같은 카드 3장째를 고르면 기존 2장이 사라지고 황금 1장이 된다 |
| **런 지속** | 얻은 카드는 스테이지(씬)를 넘어가도 유지된다 |
| **디버그 모드** | 시작 덱을 0장으로 두거나, 화면에서 직접 짤 수 있다 |

## 2. 수치

```text
BaseCost(L)   = 10 × 1.1^(L-1)          레벨업할 때마다 다음 요구치 ×1.1
Cost(L, tier) = ceil(BaseCost(L) × [1.0, 1.5, 2.0][tier])
황금 확률      = [0%, 20%, 50%][tier]    선택지 카드 1장마다 따로 굴린다
황금 데미지     = ×1.5
```

| 레벨 | 1단계 | 2단계 | 3단계 |
| :---: | :---: | :---: | :---: |
| 1 | 10 | 15 | 20 |
| 2 | 11 | 17 | 22 |
| 3 | 13 | 19 | 25 |
| 4 | 14 | 21 | 27 |

- 적 1기 = 10 EXP이므로 **1레벨 1단계는 적 한 명**에 맞춰져 있다. 이것이 표 전체의 기준점이다.
- 소모는 **그 단계 값만** 빠지고 **남은 경험치는 이월된다.** 전부 태우면 "적을 더 잡고 오면 손해"가
  되어 라운드마다 레벨업을 미룰 이유가 생긴다.
- **단계는 레벨 상승폭을 바꾸지 않는다.** 비싼 단계를 사는 이유는 오직 황금 확률이다.
  단계가 레벨까지 더 올려 주면 3단계가 언제나 정답이 되어 선택 자체가 사라진다.

### ⚠ 부동소수점 함정

`10 × 1.1`은 정확히 11이 아니라 **11.000000000000002**다. 그대로 올림하면 2레벨 1단계가
11이 아니라 **12**가 되어 표 전체가 한 칸씩 밀린다. 플레이해서는 "레벨업이 좀 비싸네" 정도로만
느껴져 알아채기가 대단히 어렵다. `ExpRules.CeilEpsilon`(1e-6)을 빼고 올린다.

## 5. 황금 데미지가 흐르는 길

이미 뚫려 있던 길을 쓴다. `SkillState.ModifyHit(HitData)`(virtual)를 `ChargeSkillState`가
오버라이드해 차징 배율을 먹인다. 황금 배율은 **차징과 곱해져야** 하므로 `SkillContext`에 실어
보낸다 — `radiusScale`이 이미 쓰는 방식 그대로다.

```text
ComboCard.Golden
  └→ ComboCard.DamageScale (1.5)
       └→ SkillContext.damageScale
            ├─ 실시간(U키)   : BulletTimeController → Ally.CastCard(…, damageScale)
            └─ 불릿타임       : ComboExecutor → new SkillContext { damageScale = … }
                 └→ SkillState.FireNextHit()
                      hit = ModifyHit(원본)              ← 차징 배율이 여기서 붙는다
                      hit.damageData.damage *= ctx.DamageScale   ← 황금이 그 결과에 곱해진다
```

- `ChargeSkillState`는 **손대지 않았다.** `ModifyHit`이 먼저 돌고 그 결과에 곱하므로 자동 합성된다.
- **넉백은 건드리지 않는다.** 황금은 데미지만 키우는 물건이다. 밀어내는 힘까지 커지면
  콤보 연계 거리가 카드 등급에 따라 달라져 체인이 무너진다.

## 6. 런 덱 — 씬을 넘어 살아남기

`BulletTimeController.BuildDeck()`이 씬이 뜰 때마다 `Ally.Equipped`로 덱을 새로 짰다.
그대로 두면 **다음 스테이지에서 얻은 카드가 전부 증발한다.**

- `RunProgression`이 런 덱의 주인이고, `GameManager`(Boot 씬, 언로드되지 않음)가 소유한다.
- `BuildDeck()`은 **첫 전투에서 한 번만** 파티 카드로 씨를 뿌리고(`SeedDeck`), 그 뒤로는 런 덱을 읽는다.

### `Seeded`와 `HasDeck`을 나눈 이유

시작 덱이 정해졌는지를 **장수로 판단하면 안 된다.** 테스트 모드는 0장으로 시작하므로,
장수로 보면 씬이 바뀔 때마다 "아직 안 짰다"로 읽고 파티 카드 16장을 도로 부어 버린다 —
모드가 조용히 꺼진 것처럼 보인다.

### `GameManager` 없이도 돈다

`RunProgression.Current`는 **절대 null이 아니다.** `GameManager`가 있으면 그쪽이 주인이고,
없으면(스테이지 씬 단독 Play) 그 판짜리 런으로 폴백한다. 그러지 않으면 Boot을 거치지 않는 한
이 시스템을 확인할 방법이 아예 없다.

## 7. 카드가 손에 들어오는 경로

레벨업으로 받은 카드는 **곧바로 손패에 꽂힌다**(`BulletTimeController.GrantCard`).

```text
[탱커] [궁수] [전사] [마법사]   ← 손패 4장 (왼쪽부터 발동)
                        ↓ 맨 오른쪽이 덱 아래로
[탱커] [궁수] [전사] [★새 카드]
```

- 버린 더미에 넣으면 덱 16장을 다 돌 때까지 — 사실상 다음 스테이지까지 — 손에 들어오지 않아
  **방금 고른 보상이 아무 일도 일으키지 않은 것처럼 보인다.**
- 밀려나는 자리를 **맨 오른쪽**으로 잡은 이유: 왼쪽부터 발동하므로 오른쪽 끝이
  유저가 짜 둔 다음 몇 수에 가장 영향이 적다.
- 밀려난 카드는 **덱 아래로** 돌아간다. 잃지 않는다.
- 합성이면 재료 2장을 **버린 더미 → 덱 → 손패** 순서로 걷어낸다. 손패는 유저가 눈으로 짜 둔
  순서라 마지막까지 아낀다. 걷어내서 빈 칸은 `RefillHand()`가 평소대로 채운다.

### 인스턴스 동일성

`CardGrantRules.Apply` · `RunProgression.Grant`는 **만들어진 카드 인스턴스를 돌려준다.**
손패에 새로 만들어 꽂으면 런 덱과 손패에 같은 카드의 몸이 하나씩 따로 생겨,
씬을 넘어갈 때 장수가 어긋난다. (`Apply_ReturnsTheVeryCardItAdded`로 못 박아 뒀다.)

## 8. 선택지 모집단 — 덱이 아니라 파티

`LevelUpSession`이 모집단을 **런 덱에서** 긁으면 테스트 모드(0장)에서 뽑을 것이 하나도 없어
`"카드가 없어서 레벨업하는데 카드가 없어서 못 받는"` 상태가 된다.

- 모집단은 `BulletTimeController.AvailableSkillPool()`이 준다 — **파티 기준**이다.
- `AvailableRoles()`가 `player.Party`에서 **살아 있는 동료**의 직업을 걷는다.
  기존 `ResolveCaster`와 같은 규칙이라 동료 사망 시 카드를 걷어내는 규칙(`purgeCardsOnAllyDeath`)과
  어긋나지 않는다.
- 직업으로 거르는 이유: 마법사가 없는데 마법사 카드를 주면 그 카드는 손패 맨 앞을 막고 영영 안 나간다.
- 직업 목록이 비면(파티 배선 전) **거르지 않는다.** 조용히 0장을 돌려주면 화면이 이유 없이 빈다.
- **합성 판정만** 지금 든 카드를 본다 — 같은 카드를 두 장 쥐고 있는지는 덱의 사실이다.

### 카탈로그 에셋

`Assets/Data/Resources/SkillCatalog.asset`은 **없어도 게임이 돈다** — 파티 장착 카드로 폴백한다.
장착되지 않은 스킬까지 선택지에 띄우려면 `Tools ▸ Prototype ▸ 스킬 카탈로그 굽기`를 실행한다.
(현재 SkillData 에셋 16개 = 파티 장착 16장이라 결과가 동일하다.)

## 9. 시작 덱 모드 — Boot 씬에서 선택

**`Boot.unity` ▸ GameManager ▸ 디버그 — 시작 덱 ▸ `Deck Startup Mode`**

| 값 | 동작 |
| :--- | :--- |
| **`Party`** (기본) | 파티 장착 카드 16장. 게임의 실제 시작 |
| **`Empty`** | **테스트 모드.** 0장으로 시작해 레벨업으로만 카드가 들어온다 |
| **`Pick`** | **디버그 모드.** 시작할 때 화면에서 카드를 직접 골라 짠다 |

- 시작 덱은 **런 단위 결정**이라 `GameManager`가 스테이지 씬의 설정을 이긴다.
  스테이지 씬 9개에 스위치를 하나씩 두면 한 곳만 어긋나도
  "2스테이지부터 갑자기 덱이 달라지는" 식으로만 드러난다.
- `BulletTimeController.standaloneStartupMode`는 **씬 단독 Play용 폴백**이다.
- 런에 **한 번만** 물어본다(`Seeded`). 다시 짜려면 메인메뉴로 나갔다 [시작]을 다시 누른다
  (`RestartRun`도 같다). 패배 후 [재시작]은 런을 리셋하지 않으므로 덱이 유지된다.

### 디버그 모드 화면 (`DeckBuilderUI`)

```text
┌──────────── 디버그 — 시작 덱 짜기 ────────────┐
│  좌클릭 +1장 · 우클릭 −1장 · 황금은 테두리가 금색  │
│ ┌──────────────────────────────────────┐ │
│ │ ┌────┐┌════┐┌────┐┌════┐┌────┐┌════┐ │ │  ← 스킬마다
│ │ │회전││회전││올려││올려││연속││연속│ │ │     일반·황금 두 칸
│ │ │강타││강타││베기││베기││사격││사격│ │ │
│ │ │일반││황금││일반││황금││일반││황금│ │ │
│ │ │ ×2 ││ ×1 ││  0 ││  0 ││  0 ││ ×3 │ │ │  ← 칸 아래 장수
│ │ └────┘└════┘└────┘└════┘└────┘└════┘ │ │
│ └──────────────────────── (스크롤) ────┘ │
│ 회전강타 ×2  회전강타(황금) ×1  연속사격(황금) ×3 │  ← 담은 목록
│ 합계 6장        [이 덱으로 시작]   [전부 지우기] │
└────────────────────────────────────────┘
```

- 우클릭은 `Button`이 알지 못하므로 `IPointerClickHandler`로 직접 받는다.
- 황금 칸을 따로 놓지 않으면 황금 데미지를 확인하려고 레벨업 확률을 기다려야 한다.
- 담은 칸은 **면색**으로 표시한다. 테두리는 등급(황금) 전용이라 겹쳐 쓸 수 없다.

## 10. 설계 결정 몇 가지

### 화면이 스스로 생성된다

`LevelUpSession` · `DeckBuilderUI`는 씬에 없으면 `RequestOpen()`이 만든다.
이 프로젝트의 전투 UI는 전부 씬 배선 0으로 스스로 지어지는데(`ComboBoardUI` · `RebindUI`),
이것만 배선을 요구하면 **이미 저장된 스테이지 씬 아홉 개에서 레벨업이 조용히 안 뜬다.**
빌더 배선(`SceneLayoutBuilder` · `TestSceneBuilder`)도 함께 넣어 뒀다 — 인스펙터 슬롯이 생긴다.

### `TimeControl.Scale`은 건드리지 않는다

그 값의 주인은 불릿타임이다. 여기서 0을 넣으면 소유자가 둘로 갈린다.
레벨업 시점엔 적이 전부 죽어 있어 멈출 것도 없다 — 입력만 잠그면 충분하다.

### `GameplayModal` — 진행 정지 창구를 하나로

스테이지 진행(웨이브 시계 · 아레나 정비 시계)과 승패 판정이 각자 개별 UI를 알게 두면,
모달이 하나 늘 때마다 세 군데를 똑같이 고쳐야 하고 한 곳을 빠뜨리면
**"카드를 고르는 사이에 등 뒤에서 웨이브가 쏟아지는"** 식으로만 드러난다.

### 난수 주입

`CardOfferRules.Build`는 `Func<float>`로 난수를 받는다. `UnityEngine.Random`을 직접 부르면
20% · 50% 경계를 검증할 방법이 없어진다. 경계가 뒤집혀 있어도 몇 십 판으로는 알아채지 못한다.
소비 순서는 **고르기 3번 → 황금 3번**이고, 테스트가 이 순서에 기댄다.

### 황금은 테두리, 상태는 면

`ComboBoardUI`의 카드 배경색은 이미 **다음 카드 / 체인 / 조준 / 집힘**을 나타내는 자리다.
등급까지 같은 채널에 실으면 둘 다 안 읽힌다. 자식은 부모 위에 그려져 카드 **뒤에** 테두리를
깔 수가 없으므로, 배경을 금색으로 칠하고 안쪽 판(`inner`)이 상태색으로 도로 덮어 링만 남긴다.

### 경험치는 적이 스스로 단다

적은 라운드 중에 계속 소환되므로 바깥에서 구독자를 관리하면
"언제 붙이고 언제 떼는가"가 통째로 새 문제가 된다. `Enemy.Start()`가 이미
`BattleRegistry.RegisterEnemy`를 하는 그 자리에서 `Combat.OnDead`를 구독한다.
오브젝트와 함께 죽는 구독이라 해제할 자리도 필요 없다.

- [ ] 카드 선택 후 단계 화면으로 돌아오고, 남은 경험치로 다시 레벨업되며 요구치가 11로 오르는지
